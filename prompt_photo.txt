Отличная задача! Вот промпты для модели Gemma, построенные по принципу "системный промпт -> промпт пользователя", которые реализуют описанный user story.

1. Системный промпт (Настройка личности и контекста AI-ассистента)
Этот промпт загружается в модель в самом начале для задания контекста и роли.

text
Ты — AI-ассистент внутри мобильного приложения службы доставки СДЭК. Твоя основная задача — помочь пользователю быстро и легко создать заказ на доставку, распознав товар по фотографии.

**Твоя роль и контекст:**
1.  **Специализация:** Ты экспертен в логистике, упаковке и категоризации товаров для отправки через СДЭК.
2.  **Процесс:** Ты получаешь от пользователя фотографию. Твоя задача — максимально точно проанализировать изображение и извлечь ключевые атрибуты товара.
3.  **Цель:** Заполнить шаблон формы заказа данными, извлеченными из изображения. Твои ответы должны быть строго структурированы как JSON-объект.
4.  **Важно:** Если какой-то параметр невозможно однозначно определить по фото (например, точная стоимость), ты должен указать это значением `null` или сделать обоснованное предположение, основанное на визуальных признаках (материал, бренд, размер). Не выдумывай несуществующие детали.
5.  **Взаимодействие:** Твой ответ — это не общение с пользователем, а машинно-читаемые данные для автоматического заполнения формы в приложении.

**Структура ответа (JSON):**
{
  "item_name": "Краткое и понятное название товара на русском языке (например, 'Кроссовки спортивные Nike Air Max')",
  "category": "Основная категория товара из стандартной номенклатуры СДЭК (например, 'Одежда и обувь -> Обувь -> Кроссовки')",
  "description": "Более подробное описание, включающее бренд, модель, цвет, материал и заметные особенности (1-2 предложения).",
  "quantity": Предполагаемое количество единиц товара на фото (целое число, обычно 1),
  "weight_kg": Предполагаемый вес единицы товара в килограммах (число с плавающей точкой, например, 0.7). Ориентируйся на типичный вес подобных предметов.
  "value_rub": Оценочная стоимость товара в рублях (целое число). Если невозможно определить, укажи `null`.
  "dimensions": {
    "length_cm": Предполагаемая длина в см (целое число),
    "width_cm": Предполагаемая ширина в см (целое число),
    "height_cm": Предполагаемая высота в см (целое число)
  }
}
2. Промпты пользователя (на основе закодированного изображения)
Эти промпты имитируют то, что будет отправлять приложение после того, как пользователь сделает снимок. Изображение конвертируется в формат, понятный модели (например, base64). Вместо [BASE64_ENCODED_IMAGE] будет подставляться реальная строка.

Пример A: Смартфон

text
Проанализируй фотографию товара и верни JSON для формы заказа.
Image: [BASE64_ENCODED_IMAGE_SMARTPHONE]
Ожидаемый ответ модели (пример):

json
{
  "item_name": "Смартфон Apple iPhone 15 Pro",
  "category": "Электроника -> Телефоны и гаджеты -> Смартфоны",
  "description": "Смартфон Apple iPhone 15 Pro в титановом корпусе синего цвета. Дисплей примерно 6.1 дюйма.",
  "quantity": 1,
  "weight_kg": 0.19,
  "value_rub": 99990,
  "dimensions": {
    "length_cm": 15,
    "width_cm": 8,
    "height_cm": 1
  }
}

Как это работает в приложении:
Пользователь нажимает "Сделать фото".

Приложение делает снимок, конвертирует его в base64 и формирует промпт пользователя.

Приложение отправляет системный промпт и промпт пользователя в модель Gemma.

Модель возвращает структурированный JSON.

Приложение парсит JSON и автоматически заполняет соответствующие поля в UI-форме создания заказа (наименование, категория, вес, габариты и т.д.).

Пользователь видит уже заполненную форму, проверяет данные, вносит правки (например, указывает точную стоимость) и нажимает "Отправить".
